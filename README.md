# VanillaRPGAssets

VanillaRPG 서버의 리소스팩과 데이터팩을 관리하는 전용 리포지토리입니다.

## 협업 워크플로우

`main` 브랜치에 코드가 push되면, GitHub Actions가 자동으로 빌드를 수행하여 `latest` 릴리즈를 갱신합니다. 
이 릴리즈가 갱신되는 순간, 라이브 서버에 접속하는 신규 플레이어들에게 리소스팩 해시 불일치 문제가 발생할 수 있습니다. 
따라서 라이브 서버의 안정성을 위해 반드시 아래의 워크플로우를 준수하여 작업해 주시기 바랍니다.

### 1. 로컬 브랜치 생성 및 작업
테스트되지 않은 에셋이 라이브 서버에 영향을 미치지 않도록, `main` 브랜치에 직접 push하지 말아야 합니다.
작업을 시작할 때 반드시 새로운 브랜치(예: `feature/puzzle-world`, `fix/datapack-enchant-bug`)를 생성하여 해당 브랜치에서 에셋을 수정합니다.

### 2. 로컬 샌드박스 테스트
수정한 에셋은 본인의 로컬 테스트 서버(vrpg-sandbox) 환경에서 충분히 검증해야 합니다.
참고로 테스트 서버를 구동(`./gradlew runSandbox`)할 때마다 로컬의 에셋 상태가 자동으로 서버에 동기화됩니다.
만일 서버 구동 중 에셋을 수정한 경우, 클라이언트 인게임에서 `F3 + T`(리소스팩)를 누르거나, 서버 채팅창에 `/reload`(데이터팩)를 입력하여 즉시 리로딩할 수 있습니다.

### 3. 원격 병합 및 배포
로컬 환경에서 검증이 완벽히 끝난 에셋만 `main` 브랜치로 병합합니다.

1. 본인의 브랜치를 원격 리포지토리에 푸시하고, 이상이 없음을 확인한 뒤 `main` 브랜치로 병합합니다.
2. 병합이 완료되면 GitHub Actions가 자동으로 새로운 릴리즈 에셋(압축 파일 및 해시)을 생성합니다. (약 1~2분 소요)
3. 릴리즈가 갱신된 것을 확인한 후, **라이브 서버 인게임에서 관리자 권한으로 `/cm reload assets` 명령어를 실행**합니다. 개발자라면 전부 권한을 드리고 있습니다.

명령어를 실행하면 라이브 서버가 재시작 없이 새로운 데이터팩을 로드하고, 접속 중인 플레이어들에게 갱신된 리소스팩을 원활하게 재전송하여 배포가 완료됩니다.
